# Design: add-connector-desktop-control

> 接续 `add-connector-local-tools`（v2 受控执行）与 `add-connector-mcp-proxy`（v2.5）。本文为 v3 受控桌面控制的规格化摘要与决策记录。这是连接器路线图中能力最强、风险最高的一档。

## Context

v2 已建立协议 v2、request-id + 流式机制、per-device/per-tool 授权、`auto`/`webui`/`local` 审批、设备主人主权、双端审计。v3 在此之上加"看屏幕 + 动键鼠"的实时会话式控制，覆盖没有 CLI/MCP 接口的任意 GUI 软件（用户最初的"打开 QQ 并登录"即典型场景）。nanobot 已支持多模态 LLM provider，可承载 computer-use 式决策循环。

约束延续前序：Python 3.11+ asyncio、不引入重量级依赖、用户电脑不可开公网端口、服务端不可信、复用优先。新增约束：屏幕内容与键鼠控制是最高敏感度能力，隐私与人类在环是硬性设计约束而非可选项。

## Goals / Non-Goals

**Goals:**

- 设备主人显式开启一次限时"受控桌面会话"后，服务端多模态 LLM 能看屏幕、决策、经连接器注入键鼠，完成 GUI 操作。
- 全程人类在环：设备主人可随时接管/终止，敏感动作触发二次确认。
- 隐私优先：捕获仅在活动会话内、结束即停、帧默认不落盘、本机醒目指示。
- 沿用 v2 授权/主权/审计，不新开安全模型；桌面策略比 v2 更严（无 `auto`）。
- 默认关闭（`allowDesktopControl: false`），与 `allowExec` 独立。

**Non-Goals:**

- 无人值守全自动 GUI 操作（始终要求会话授权 + 可接管）。
- 后台静默截屏 / 绕过操作系统权限提示（macOS 屏幕录制/辅助功能授权仍走系统层）。
- 像素级精确回放/宏录制、多设备并行桌面编排（后续再议）。
- 代替 v2/v2.5：能用命令或 MCP 完成的操作应优先走 v2/v2.5，桌面控制是最后手段。

## Decisions

1. **会话式而非单发：受控桌面会话是一等生命周期对象**
   `desktop.session.start` 开启限时会话，期间 `desktop.capture` 流式回帧、`desktop.input` 下发动作，`desktop.session.end` 或超时/接管终止。会话外一律不可截屏或注入。作为有状态多步交互，Agent 侧以长任务型工具承载（参照 `long_task.py`）。

2. **强制人类在环，取消 `auto`**
   桌面控制不提供 v2 的 `auto` 策略。开启会话必须设备主人在本机显式授权（限时）；会话内提供一键接管（暂停 Agent 控制、人接手）与终止；这是"完全掌控他人电脑"风险下的不可协商约束。

3. **敏感动作二次确认**
   连接器/服务端对疑似敏感动作（在密码类输入框输入、点击含"支付/确认/删除/授权"等语义的控件、系统弹窗）触发额外确认。宁可打断也不误操作，缓解模型误判造成不可逆后果。

4. **隐私：帧默认不落盘 + 捕获指示 + 结束即停**
   屏幕帧默认仅在内存中流转、不持久化；仅当设备主人显式开启"录制"才留存并在 UI/审计标注。捕获期间连接器本机显示醒目指示（托盘高亮/边框）。会话结束立即停止捕获与释放系统资源。

5. **多模态决策循环在服务端，动作翻译分层**
   服务端把屏幕帧喂多模态 LLM，模型输出高层动作（"点击登录按钮"/"输入用户名"），经动作翻译层转为坐标点击/键入事件下发。翻译层做边界校验（坐标在屏内、事件类型白名单），并把每个动作与其截图上下文写入逐动作审计，供回放。

6. **跨平台捕获/注入后端隔离**
   捕获（全屏/指定窗口，帧率与分辨率上限）与注入（键鼠事件）以后端接口隔离，Windows/macOS/Linux 各自实现；macOS 需引导用户在系统"屏幕录制/辅助功能"授权。后端不可用时会话优雅拒绝并给出系统级授权指引。

7. **资源上限与会话超时**
   帧率上限、分辨率上限、会话最长时长、空闲超时；超限/超时自动结束会话。防止长时高帧率捕获吃满带宽/内存，也限制单次授权的暴露窗口。

8. **沿用 v2 授权与审计，桌面策略更严**
   设备主人主权、per-device 授权、双端审计全部适用；桌面会话审计粒度细到每个注入动作 + 触发它的截图上下文。桌面能力开关 `allowDesktopControl` 与 `allowExec` 独立，可单独治理。

## Risks / Trade-offs

- [完全掌控他人电脑的极高风险] → 强制会话授权 + 限时 + 可接管终止（决策 1、2）、无 `auto`、敏感动作二次确认（决策 3）、逐动作审计（决策 5）、专项隐私评估 + 渗透测试门禁方可 GA。
- [屏幕内容泄露隐私] → 帧默认不落盘 + 捕获指示 + 结束即停（决策 4）；录制须显式开启并标注；文档明确多用户/受控他人电脑的知情同意。
- [多模态模型误操作导致不可逆后果] → 敏感动作二次确认（决策 3）、动作边界校验（决策 5）、人可随时接管；关键操作建议人工执行。
- [高帧率捕获吃满带宽/内存] → 帧率/分辨率/会话超时上限（决策 7）；按需截图而非持续全速流。
- [操作系统权限被误绕过预期] → 不绕过系统授权（Non-Goal + 决策 6）；缺授权时优雅拒绝并引导。
- [坐标/分辨率错配导致误点] → 动作翻译层做坐标归一化与屏内校验（决策 5），上报显示器信息。
- [会话被恶意服务端滥用] → 会话必须本机授权开启、限时、可接管；捕获指示让用户始终知情。

## Migration Plan

1. 服务端随常规版本发布，`allowDesktopControl` 默认 false —— 零行为变化。
2. v3 连接器发版；用户升级并在系统层授予屏幕录制/辅助功能权限后，桌面能力方可用。
3. 试点：单用户在自己电脑上开受控会话，用低敏感任务（如"打开某应用并点到某页面"）验证 授权→捕获→决策→注入→接管→终止→审计回放 全链路。
4. 回滚：关闭 `allowDesktopControl`，桌面会话不可开启，v2/v2.5/v1 能力不受影响。
5. 隐私影响评估 + 渗透测试通过后 GA，再 `openspec archive add-connector-desktop-control`。

## Open Questions

- 敏感动作识别用启发式（控件文案/输入框类型）还是额外模型判定？→ v3 先启发式 + 密码框检测，误判反馈再增强。
- 会话是否允许 Agent 与人交替控制（协作模式）还是仅"Agent 控制 / 人接管"二态？→ 倾向先二态，协作模式后续议。
- 帧传输编码（JPEG/WebP 质量与增量差分）如何在清晰度与带宽间取舍？→ 灰度实测定档位。
- 多用户"受控他人电脑"场景的合规基线（知情同意留证）？→ 需法务/合规评审，可能限定仅本人设备先行。
- 桌面会话与 v2 执行、v2.5 MCP 的组合优先级（同一任务如何选择最低风险路径）？→ Agent 侧策略后续设计。
