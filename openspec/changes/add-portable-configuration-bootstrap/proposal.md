# Proposal: add-portable-configuration-bootstrap

## 为什么

nanobot 当前已具备两类配置：服务端使用 `~/.nanobot/config.json`，每台连接器使用 `~/.nanobot-connector/` 下的本机配置、工具注册表和凭据。然而，新服务器或新设备的部署仍依赖人工编辑 JSON、记忆字段、逐项创建本机工具。版本升级时虽可用 `nanobot onboard --refresh` 补充部分默认字段，但没有显式版本号、统一校验、部署诊断、可发布模板或连接器模板导入流程。

这会带来三个问题：

- 新服务器难以在不复制私密运行状态的前提下完成可重复部署；
- 新连接器设备可能被错误地复制 `deviceToken`、配对记录或授权状态，破坏设备身份边界；
- QQ、浏览器和自动化脚本等本机工具没有安全、可检查、可重复的导入路径。
- 当前重配对会在网络请求成功前改写本机服务端地址，失败时可能留下“新地址 + 旧 token”的不一致状态；配置、备份和凭据文件的权限与日志脱敏也未形成生产级约束。

本变更建立“模板可迁移、身份需重新配对、密钥不落模板、默认最小权限”的配置生命周期。

## 变更内容

- **服务端配置版本化**：在根 `Config` 中引入序列化字段 `schemaVersion`，将现有的兼容处理组织为按版本执行的迁移链。旧的无版本配置视为首个兼容版本；迁移仅补全或重命名已知字段，不丢弃用户的有效配置。
- **统一配置生命周期命令**：新增 `nanobot config init`、`nanobot config refresh`、`nanobot config validate` 和 `nanobot config doctor`。现有 `nanobot onboard` 保持兼容，并复用初始化/刷新逻辑。
  - `init` 从安全模板和 Schema 默认值创建目标配置；若目标已存在，除非显式 `--force`，否则拒绝覆盖。
  - `refresh` 只做版本迁移与缺失默认字段补齐，保留已配置值，且不写入环境变量中解析出的密钥值。
  - `validate` 不改写文件，校验 JSON、Schema、模板约束和环境变量引用；提供严格模式检查运行所需密钥。
  - `doctor` 不改写配置，检查工作区、端口、文件权限、连接器开关和部署依赖，并给出可执行的修复建议。
- **可发布的安全模板**：随安装包发布服务端 `config.example.json` 和连接器工具档案。模板只包含非敏感结构、默认值和 `${环境变量}` 引用；不得包含 API Key、设备 token、配对码、授权记录、审计数据或个人目录。
- **部署档案与导出**：区分内置通用模板与项目拥有的部署档案。提供 `nanobot config export-profile`，从现有配置生成需人工审阅的无密钥部署档案；提供连接器工具档案导出能力。导出默认脱敏、拒绝设备身份和内联凭据，且不把机器专属绝对路径当作可移植档案。
- **可审计的来源与安全写入**：定义配置来源优先级和每个字段的来源诊断；在 Pydantic 校验前解析 `${环境变量}`，但绝不回写解析值。任何会写文件的命令都使用目标级互斥锁、`fsync`、原子替换、受限权限备份和脱敏变更记录；支持 `--dry-run`、`--json` 以服务自动化。
- **连接器本机初始化与模板导入**：新增 `nanobot-connector init`、`nanobot-connector tool import-template` 和 `nanobot-connector doctor`。
  - `init` 仅创建本机安全默认配置和空注册表，不会连接服务端、不会生成或复用设备身份、不会自动共享目录或开启桌面控制。
  - 用户明确选择档案后才导入工具模板。导入前检查可执行文件和参数约束；导入不执行程序、不导入凭据，并对同名工具默认失败而不是覆盖。
  - GUI 首次启动提供与 CLI 等价的档案选择、依赖检查和失败原因展示。
- **重配对与本机凭据加固**：切换到新服务器时，连接器必须以候选配置完成 TLS 校验和配对，再原子替换旧身份；不同服务器须显式确认。证书指纹必须真实校验，不得把“跳过验证”误称为固定证书。工具凭据改用操作系统凭据库；旧的 `secrets.json` 仅可在本机显式迁移，严格模式下不允许不安全回退。
- **迁移边界明确化**：换新服务器时默认创建空的设备/授权运行状态，所有连接器必须重新配对；同一服务器上的版本升级则保留运行状态。不得提供复制旧 `devices.json`、`grants.json` 或 `deviceToken` 的自动迁移路径。
- **运行生效语义**：配置命令不承诺热更新。对正在运行的网关，刷新后明确报告“需重启才生效”；诊断只把端口占用等检查作为建议，不能消除启动时竞争。
- **文档与发布**：补充中文的部署、升级、换服务器、换设备和回滚手册；确保模板被 wheel 与连接器发布产物包含。

## 能力

### 新增能力

- `configuration-bootstrap`：服务端配置模板、版本迁移、初始化、校验和部署诊断，以及安全的迁移行为定义。

### 修改能力

- `connector-client`：连接器本机配置版本化、显式初始化、工具档案导入、依赖诊断和无凭据迁移规则。

## 不做的事

- 不自动把 `.env` 当作生产密钥存储；生产密钥由系统环境变量、服务管理器或密钥服务注入。
- 不把设备 token、配对记录、授权、审计、登录态或本机凭据放入 Git、模板或服务端配置。
- 不在新服务器初始化时自动恢复任意设备的信任关系；重新配对是安全要求。
- 不通过本变更实现聊天会话到设备 A/B 的绑定；该问题由独立的会话级设备绑定变更处理。
- 不自动启用 `allowExec`、`allowMcpProxy`、`allowDesktopControl`，也不自动共享任何目录。

## 影响

- **服务端代码**：`nanobot/config/schema.py`、`nanobot/config/loader.py`、CLI 注册与新的配置生命周期模块；所有调用 `load_config` 的路径需保持兼容。
- **连接器代码**：`connector/nanobot_connector/config.py`、`pairing.py`、`tools.py`、凭据后端、`cli.py`、`gui.py`，并增加安全模板加载与诊断逻辑。
- **发布内容**：增加 package data、模板、中文部署文档与端到端测试。
- **兼容性**：旧配置自动迁移；现有 `nanobot onboard`、`nanobot-connector pair`、`tool add` 等命令继续可用。新命令默认不覆盖已有配置。
- **安全性**：默认关闭高风险连接器能力；模板与运行状态物理分离；部署到新服务器时强制重新建立设备信任。
