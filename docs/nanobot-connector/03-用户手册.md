# nanobot Connector 用户手册

> 原理概述见 [00-连接器说明](./00-连接器说明.md)。

## 适用场景

网关部署在服务器上，资料在本地电脑。安装连接器后，Agent 可按需读取你**显式共享**的文件夹内容（例如做 PPT 时拉取本地文档），无需事先整包上传。

## 前置条件

- 网关已开启连接器：`connector.enabled: true`（修改 `~/.nanobot/config.json` 后重启 gateway）
- 你的电脑能**出站访问**网关地址（通常为 `wss://<host>:8765`）

## 安装与配对

1. 在 WebUI **Settings → Devices** 点击 **Add device**，按向导操作。
2. 在本机安装 `nanobot-connector`（从 Release 或管理员提供的安装包）。
3. 在向导中复制配对码，在本机执行：

```bash
nanobot-connector pair --server wss://<网关地址> --code <8位配对码>
```

内网自签证书时，首次配对需固定证书指纹：

```bash
# 先查看证书指纹（示例）
openssl s_client -connect <host>:8765 -servername <host> </dev/null 2>/dev/null | openssl x509 -fingerprint -sha256 -noout

nanobot-connector pair --server wss://<host>:8765 --code <配对码> --fingerprint <SHA256指纹>
```

4. 配对成功后执行 `nanobot-connector start`（或 `service install` 开机自启）。

## 共享目录

仅白名单内目录可被 Agent 读取（只读）：

```bash
nanobot-connector allow "D:\PPT资料"
nanobot-connector allow "E:\文档"
nanobot-connector status   # 查看已共享目录与连接状态
```

禁止共享盘符根目录（如 `C:\`）。连接器本地会记录审计日志（`~/.nanobot-connector/logs/`）。

## 在对话中使用

配对并共享目录后，在 WebUI 对话中直接说明需求，例如：

> 用我电脑上 D:\PPT资料 里的调研报告做一份 PPT

Agent 会通过 `connector_*` 工具列出文件、拉取到服务器工作区后生成 PPT。

## 受控执行本地工具（v2）

> 需要网关开启 `connector.allowExec: true`（默认关闭）。关闭时本节全部功能不可用，只读文件能力不受影响。

除了读取文件，连接器还能让 Agent **调用你在本机显式登记的程序/脚本**（例如打开某个软件、运行一段只读诊断脚本）。这不是给服务器开一个任意命令行——服务器只能按名字调用你登记好的工具，参数受模板校验，且**从不经过 shell**。

### 登记一个工具

工具定义写在本机 `~/.nanobot-connector/tools.json`，用 CLI 管理：

```bash
# 简单无参工具（例如打开记事本）
nanobot-connector tool add --name open_notepad --exec "C:\Windows\notepad.exe" --approval local

# 从 JSON 文件登记带参数的工具
nanobot-connector tool add --file mytool.json

nanobot-connector tool list           # 查看已登记工具
nanobot-connector tool show open_notepad   # 查看服务器可见的工具模式
nanobot-connector tool remove open_notepad
```

`mytool.json` 示例（参数模板 + 无 shell 执行）：

```json
{
  "name": "grep_logs",
  "description": "在日志目录内按关键词检索（只读）",
  "exec": "rg",
  "approval": "webui",
  "params": [
    { "name": "keyword", "type": "string", "required": true, "pattern": "[\\w\\-]+" },
    { "name": "dir", "type": "path", "required": true, "allowedDir": "D:\\logs" }
  ],
  "argv": ["{keyword}", "{dir}"]
}
```

- 参数类型：`string`（可配 `pattern` 正则全匹配）、`int`（可配 `min`/`max`）、`enum`（配 `choices`）、`path`（**必须**配 `allowedDir`，值被限制在该目录内）。
- 未在 `params` 声明的参数一律拒绝；参数值作为单个 `argv` 元素传入，`; rm -rf` 之类只是普通字符串。
- 服务器与其他人**不能**远程新增或修改你的工具定义。

### 审批策略

每个工具用 `approval` 声明谁来放行每次执行：

| 策略 | 行为 | 适用 |
|---|---|---|
| `auto` | 授权范围内直接执行 | 仅建议自用的低危工具 |
| `webui` | 服务端弹审批卡片，需在 WebUI 放行 | 有一定影响的工具 |
| `local` | 连接器本机确认后才执行 | 高危工具的最后闸门（默认） |

`webui` 审批在 **Settings → Devices** 顶部以卡片出现，展示工具名、脱敏参数摘要与发起者；无人响应到 `approvalTtlS`（默认 120s）即**按拒绝**处理。

### 工具需要密钥时

若工具需要 token/密钥，只在本机配置，**永不经协议或服务器传输**：

```bash
nanobot-connector tool secret set my-api-token   # 交互式输入，隐藏回显
nanobot-connector tool secret list               # 只列 id，不显示值
```

在工具定义里用 `"secrets": { "API_TOKEN": "my-api-token" }` 引用，执行时注入子进程环境变量。审计与审批卡片里只出现引用名，不出现明文。

### 让别人的 Agent 用你的电脑（跨人授权）

当使用服务器的人（操作者）不是设备主人时，默认**看不到也用不了**你的工具。要开放：

1. 对方（或其 Agent）发起访问请求；你在 **Settings → Devices → 管理 → 授权** 看到"待处理访问请求"。
2. 你可**接受**（授予其请求的工具）或**拒绝**；也可主动"授权给其他操作者"，并设**有效期**（1 小时 / 1 天 / 永不过期等）。
3. "活跃使用者"列表显示当前谁在用你的设备、用了哪些工具，可**一键收回**，即时生效。

设备工具的定义权、授权权、审批权、终止权始终在你本机——服务器无法越权。

### 在对话中调用工具

配对并开启执行后，在对话中直接说明，例如：

> 在我台式机上打开记事本

Agent 会用 `connector_list_tools` 发现工具，再用 `connector_call_tool` 调用（多台设备时需指明是哪台——可在设备管理里给设备起个别名，如"台式机")。

## 桥接本地 MCP server（v2.5）

> 需要网关开启 `connector.allowExec: true` 且 `connector.allowMcpProxy: true`（默认均关闭）。

如果你本机已经跑着（或愿意安装）**MCP server**（浏览器控制、文件索引、数据库、笔记等），不必逐个登记为本地工具——直接把整个 server 桥接给服务器，它的所有工具一次性可用。连接器在你本机作为 MCP 客户端连它们，服务器**不直连你的电脑**，也不暴露任何端口。

### 登记一个本机 MCP server

沿用 nanobot 的 MCP 配置形态（stdio / SSE / streamable-HTTP），写在本机 `~/.nanobot-connector/mcp.json`：

```bash
# stdio 快捷形式
nanobot-connector mcp add --name filesearch --command "my-mcp-server" --approval webui

# 从 JSON 文件登记（可含 args/env/url/enabledTools 等）
nanobot-connector mcp add --file myserver.json

nanobot-connector mcp list
nanobot-connector mcp remove filesearch
```

`myserver.json` 示例：

```json
{
  "name": "filesearch",
  "command": "uvx",
  "args": ["some-mcp-server"],
  "approval": "local",
  "secrets": { "API_TOKEN": "my-token-id" },
  "enabledTools": ["search", "get_snippet"]
}
```

- `secrets` 引用本机凭据（`nanobot-connector tool secret set my-token-id` 配置），只注入 server 子进程环境，**不经协议/服务器**。
- `enabledTools` 只桥接列出的工具（`["*"]` 为全部），避免把过多工具灌进 Agent。
- `approval` 同受控执行：`auto` / `webui`（服务端审批卡片）/ `local`（本机确认）。

### 在对话中使用

Agent 用 `connector_list_mcp_tools` 发现桥接工具、用 `connector_call_mcp_tool` 调用。授权与审批**完全沿用受控执行那套**：跨人使用需设备主人授予（可限时），未授权返回等同"工具不存在"。设备离线时其桥接工具自动注销。

在 **Settings → Devices → 管理 → 本地工具** 标签下的"本地 MCP server"分区，可查看已桥接 server、其工具与连接健康。

## 受控桌面控制（v3）

> 需要网关开启 `connector.allowDesktopControl: true`（默认关闭），且设备本机开启 `desktop_enabled` 并授予系统屏幕录制/辅助功能权限。这是**风险最高**的能力，请谨慎开启。

对于没有命令行/MCP 接口的图形软件，Agent 可以"看屏幕 + 动键鼠"来操作（截图 → 判断 → 点击/输入 → 再截图的闭环）。安全上强制**人在环**：

- **每次会话都需你本机确认**：服务器发起会话时，你的电脑会弹确认；不同意就不开。**没有 `auto`**。
- **限时**：会话有最长时长与空闲超时，到点自动结束。
- **敏感动作二次确认**：点"支付/确认/删除/授权"类控件、或向密码框输入，会在 WebUI 弹确认卡片，未确认不执行。
- **随时接管/终止**：在 **Settings → Devices → 管理 → 本地工具** 的"桌面控制会话"里可一键接管/终止。
- **隐私**：屏幕帧**默认只在内存流转、不落盘**；仅当显式开启录制才留存，且按保留期到期自动删除、可手动删除；捕获期间你的电脑显示醒目指示。

### 本机开启

```bash
nanobot-connector desktop enable          # 本设备开启桌面控制能力
# Windows 10/11 无单独“屏幕录制”授权页；连接器须运行在当前已登录用户的桌面会话中。
# macOS 需在系统设置中授予屏幕录制和辅助功能权限。
nanobot-connector start                    # 运行守护进程
```

### 本机同意（arm 时间窗）

`local` 审批的工具/MCP、以及**所有桌面会话**默认 fail-closed——守护进程不会擅自放行。你在本机用 **arm** 预授权一个限时窗口（贴合无人值守服务，类似 OpenClaw 的 arm）：

```bash
nanobot-connector arm desktop --for 30m    # 30 分钟内允许开桌面会话
nanobot-connector arm exec --for 1h        # 允许 local 审批的工具执行
nanobot-connector arm mcp  --for 30m       # 允许 local 审批的 MCP 调用
nanobot-connector arm status               # 查看剩余时间
nanobot-connector disarm desktop           # 立即收回（或 disarm all）
```

未 arm 时，对应能力一律被本机拒绝；arm 到期自动失效，无需重启守护进程。

### 在对话中使用

> 在我的台式机上打开设置并进入蓝牙页面

Agent 用 `connector_desktop_session` 开启会话（你本机确认后返回首屏截图），再用 `connector_desktop_act` 按截图点击/输入、`connector_desktop_end` 结束。全过程逐动作审计。

## 吊销设备

在 **Settings → Devices** 中对设备点击 **Revoke** 并确认。吊销后该设备约 10 秒内断开，旧令牌无法重连，需重新配对。

## 常见问题

| 现象 | 处理 |
|---|---|
| WebUI 没有 Devices 菜单 | `connector.enabled` 为 false 或未重启网关 |
| 配对失败 / 证书错误 | 使用 `--fingerprint` 固定自签证书 |
| Agent 说设备离线 | 本机运行 `nanobot-connector start` 或检查网络/防火墙 |
| 路径被拒绝 | 在本机 `allow` 该目录后重试 |
| 设备管理里没有"管理"按钮 / 无本地工具标签 | 网关未开启 `connector.allowExec` |
| Agent 说工具不存在 | 未登记该工具，或跨人使用未获授权（等同 not_found）|
| Agent 说执行未获批准 | `webui`/`local` 审批被拒或超时；重试并及时放行 |
| 工具报缺少凭据 | 本机 `nanobot-connector tool secret set <id>` 配置后重试 |
| 设备详情没有"本地 MCP server"分区 | 网关未开启 `connector.allowMcpProxy`，或未登记 MCP server |
| MCP 工具报不可用 | 本机 MCP server 未就绪/已退出；连接器会自动重连，稍后重试 |
