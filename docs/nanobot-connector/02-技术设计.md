## 1. 概述

### 1.1 问题

nanobot 部署在服务器上（例：`192.168.90.100`），Agent 的 `read_file` / `exec` 等工具只能触达**服务器文件系统**。用户本地电脑上的资料 Agent 无法访问，导致"基于我电脑上的资料做 PPT"这类任务无法闭环。

### 1.2 方案

引入 **nanobot Connector**：一个安装在用户电脑上的轻量守护进程，采用与 CMDB 采集器相同的**反向连接**模式：

1. 用户从 WebUI 下载连接器，安装后输入**一次性配对码**完成设备绑定；
2. 连接器向网关发起**出站 WSS 长连接**（客户端 → 服务端，天然穿透 NAT/防火墙，无需在用户电脑开端口）；
3. 用户显式配置**共享目录白名单**（如 `D:\PPT资料`）；
4. 服务端 Agent 通过新增的 `connector_*` 工具，按需列目录 / 搜索 / 读取 / 拉取白名单内的文件到服务器工作区，再用现有文件工具与技能完成 PPT 制作。

### 1.3 设计原则

- **复用现有技术栈**：Python 3.11 + asyncio + `websockets` + pydantic + typer；WebUI 沿用 React/TS/Vite；不引入新的重量级依赖（无 gRPC、无消息队列）。
- **复用现有基础设施**：接入网关现有的 `websockets.serve(process_request=...)` HTTP/WS 分发（`nanobot/channels/websocket.py`）、`GatewayServices` 服务容器、工具自动发现（pkgutil + entry points）、pydantic 配置（camelCase 别名）。
- **默认最小权限**：只读、目录白名单、单文件大小上限、能力开关默认关闭高危项（本地 exec 在 v1 不开放）。
- **控制面与数据面同通道**：v1 所有 RPC 与文件分块都走同一条 WSS 多路复用连接，避免额外端口与证书管理成本。

### 2.1 关键数据流："用本地资料做 PPT"

```
用户(WebUI): "用我电脑 D:\PPT资料 里的调研报告做一份 PPT"
  1. AgentLoop 收到消息，LLM 决定调用工具
  2. connector_list_nodes() → ConnectorHub 返回在线设备 [dev-a1b2 "Xu 的台式机"]
  3. connector_list_files(node="dev-a1b2", path="D:/PPT资料")
       → Hub 生成 rpc_request(fs.list) → 经 WSS 下发 → 连接器校验白名单后返回文件清单
  4. connector_fetch_file(node="dev-a1b2", path="D:/PPT资料/调研报告.docx")
       → 连接器分块回传 → Hub 组装校验(sha256) → 落盘
         <workspace>/connector/dev-a1b2/PPT资料/调研报告.docx → 工具返回服务器路径
  5. Agent 用现有 read_file / exec(python-pptx) 等工具生成 PPT
  6. 产物经 WebUI 媒体通道回传给用户下载
```

## 3. 服务端设计

### 3.1 模块布局

```
nanobot/connector/
├── __init__.py
├── protocol.py        # 协议帧 pydantic 模型 + PROTOCOL_VERSION
├── hub.py             # ConnectorHub：节点生命周期、RPC 路由、pending futures
├── devices.py         # DeviceStore：配对码/设备令牌 签发·校验·吊销（JSON 持久化）
├── transfer.py        # 分块接收器：乱序缓冲、sha256 校验、原子落盘
└── http_routes.py     # /api/connector/* 管理端 HTTP 路由（配对码、设备列表、吊销）

nanobot/agent/tools/connector.py    # Agent 工具（ToolLoader pkgutil 自动发现）

connector/                          # 客户端子项目（独立打包，见 §5）
```

### 3.2 网关接入

复用 `WebSocketChannel` 已有的 `process_request` HTTP 分发链（`_dispatch_http`）。在 `GatewayHTTPHandler` 注册两类路由：

| 路由 | 类型 | 鉴权 | 说明 |
|---|---|---|---|
| `GET /connector/ws` | WS 升级 | 设备令牌（握手 query `device_token`，常量时间比较，参照 `_authorize_websocket_handshake` 的 `hmac.compare_digest` 做法） | 连接器数据通道 |
| `POST /api/connector/pairing-codes` | HTTP | WebUI 既有会话鉴权 | 生成一次性配对码 |
| `POST /connector/pair` | HTTP | 配对码本身 | 连接器用配对码兑换设备令牌 |
| `GET /api/connector/nodes` | HTTP | WebUI 既有会话鉴权 | 设备列表（在线状态/平台/共享目录摘要） |
| `DELETE /api/connector/nodes/{id}` | HTTP | WebUI 既有会话鉴权 | 吊销设备 |

`ConnectorHub` 实例挂到 `GatewayServices`（由 `build_gateway_services` 创建），与 `tokens` / `media` / `workspaces` 并列，随网关生命周期启停。

### 3.3 ConnectorHub

```python
class ConnectorHub:
    """连接器节点注册表 + RPC 路由。全部状态驻留内存，节点断开即摘除。"""

    _nodes: dict[str, ConnectorNode]          # node_id -> 连接与能力清单
    _pending: dict[str, asyncio.Future[Any]]  # rpc_id -> 等待响应的 future

    async def attach(self, connection, register_frame) -> ConnectorNode
    async def detach(self, node_id) -> None
    def list_nodes(self) -> list[NodeInfo]

    async def rpc(self, node_id: str, method: str, params: dict,
                  *, timeout: float) -> Any:
        """下发 rpc_request，await 对应 rpc_response；超时抛 ConnectorRpcTimeout。"""

    async def fetch_file(self, node_id: str, path: str,
                         dest_dir: Path, *, max_bytes: int) -> FetchResult:
        """发起 fs.fetch，接收 file_chunk 流，sha256 校验后原子落盘（临时文件+rename）。"""
```

要点：

- **RPC 关联**：`rpc_id = uuid4().hex`，响应帧按 id 唤醒 future；连接断开时所有 pending future 以 `ConnectorDisconnected` 失败，Agent 工具将其转换为 `ToolResult.error`（现有 registry 会附加重试提示）。
- **心跳**：沿用 `websockets` 内建 ping/pong（`ping_interval` / `ping_timeout` 配置项与既有通道一致）；应用层 `heartbeat` 帧另带节点负载摘要（在线目录数、版本号），用于设备页展示。
- **并发限制**：每节点同时进行的文件传输数由 `maxConcurrentTransfers` 限制，超出的 `fetch_file` 排队。
- **落盘**：写 `<workspace>/connector/<node_id>/<安全相对路径>`，先写 `.part` 临时文件，校验通过后 `rename`（与 `nanobot/agent/memory.py` 的原子写风格一致）。
- **落盘路径 sanitize（服务端防线）**：客户端路径视为不可信——剥离盘符/根（`D:\PPT资料\a.docx` → `D/PPT资料/a.docx`）、替换非法字符、消解 `.`/`..`，最终 `resolve()` 后必须仍位于 `<workspace>/connector/<node_id>/` 内，否则拒绝传输并审计。该防线与客户端白名单相互独立：即使连接器被攻破，也无法写出落盘区。
- **磁盘配额**：`fetchCacheMaxBytes` 约束落盘区总量，超限先按 LRU（最后访问时间）清理旧文件；单文件超过配额直接 `too_large`。
- **传输取消**：调用方超时（`transferTimeoutS`）或 Agent 回合取消时，Hub 下发 `cancel` 帧、清理 `.part` 临时文件、丢弃该 `id` 后续分块。

### 3.4 DeviceStore（配对与令牌）

参照 `nanobot/pairing/` 的配对码模式与 `GatewayTokenStore` 的令牌管理：

- **配对码**：8 位大写字母数字，TTL 10 分钟，一次性；由 WebUI 管理端生成，记录生成者身份作为设备归属。
- **配对端点防暴力**：`POST /connector/pair` 无鉴权，因此：同一来源 IP 失败 5 次锁定 15 分钟（429）；全局失败频率超阈值时作废全部未兑换配对码并告警；配对码常量时间比较。
- **设备令牌**：配对成功后签发 `secrets.token_urlsafe(32)`；服务端仅存 `sha256(token)`，明文只在兑换响应中出现一次，由连接器保存在本地配置。
- **机器指纹去重**：兑换请求携带机器指纹（主机名 + 稳定机器标识哈希）；同指纹重新配对时复用原设备记录并吊销旧令牌，避免僵尸设备。
- **持久化**：`<workspace>/connector/devices.json`，原子写 + fsync（复用现有工具函数），结构：

```json
{
  "devices": [
    {
      "nodeId": "dev-a1b2c3",
      "name": "Xu 的台式机",
      "platform": "windows",
      "ownerId": "webui:xu",
      "machineFingerprint": "…",
      "tokenSha256": "…",
      "createdAt": "2026-07-14T02:00:00Z",
      "lastSeenAt": "2026-07-14T03:12:45Z",
      "revoked": false
    }
  ]
}
```

- **吊销**：置 `revoked: true` 并立即断开在线连接；被吊销令牌的握手一律 401。
- **归属隔离**：多用户部署时，`connector_*` 工具与 `/api/connector/*` 管理路由按 `ownerId` 过滤；跨用户访问返回等同 `not_found` 的错误，不泄露设备存在性。单用户部署不受限。

### 3.5 Agent 工具

新增 `nanobot/agent/tools/connector.py`，继承 `Tool`（`nanobot/agent/tools/base.py`），由 `ToolLoader` 的 pkgutil 扫描自动发现，`connector.enabled=false` 时不注册（参照 `FileToolsConfig` 开关模式）：

| 工具 | 参数 | 行为 |
|---|---|---|
| `connector_list_nodes` | — | 在线设备列表（node_id、名称、平台、共享根目录） |
| `connector_list_files` | `node_id, path, max_entries?` | 列目录（名称/大小/mtime/类型），仅白名单内 |
| `connector_search_files` | `node_id, query, path?` | 文件名模糊搜索（客户端执行，返回 TopN） |
| `connector_read_file` | `node_id, path, max_bytes?` | 小文本文件直接内联返回（默认上限 256KB） |
| `connector_fetch_file` | `node_id, path` | 拉取文件到服务器工作区，返回服务器端路径 |

所有工具将 `ConnectorRpcTimeout` / `ConnectorDisconnected` / 白名单拒绝映射为带修复提示的 `ToolResult.error`（例如"设备离线，请提示用户检查连接器是否运行"），便于 LLM 自我纠错或向用户转述。

### 3.6 配置 Schema

`nanobot/config/schema.py` 新增（pydantic，camelCase 别名，与现有 `ToolsConfig`/通道配置同风格）：

```json
{
  "connector": {
    "enabled": false,
    "path": "/connector/ws",
    "pairingCodeTtlS": 600,
    "rpcTimeoutS": 60,
    "transferTimeoutS": 600,
    "maxFileBytes": 209715200,
    "maxInlineReadBytes": 262144,
    "maxConcurrentTransfers": 2,
    "chunkBytes": 262144,
    "fetchCacheMaxBytes": 2147483648,
    "allowExec": false
  }
}
```

说明：`rpcTimeoutS` 只作用于非传输 RPC；`fs.fetch` 整体受 `transferTimeoutS` 控制。`fetchCacheMaxBytes` 约束 `<workspace>/connector/` 总占用，超限按 LRU 清理旧文件。

`allowExec` 为 v2 预留（远程执行能力），v1 恒为 false 且客户端不实现。

## 4. 通信协议

### 4.1 传输与编码

- 单条 WSS 连接，JSON 文本帧（与 WebUI 通道一致，`ensure_ascii=False`）；文件内容以 base64 分块内嵌（`chunkBytes` 默认 256KB，base64 后约 341KB，低于通道 `max_message_bytes`）。
- 协议带版本号：注册帧 `protocol: 1`。服务端遇到不支持的版本回 `error(code="protocol_unsupported")` 并关闭；高版本客户端负责向下兼容。

### 4.2 帧定义

**连接器 → 服务端**

```jsonc
{"type": "register", "protocol": 1, "node": {
    "name": "Xu 的台式机", "platform": "windows",
    "version": "1.0.0", "roots": ["D:/PPT资料", "E:/文档"]}}
// 握手 query 携带 device_token；register 必须是首帧，10s 未注册即断开

{"type": "heartbeat", "ts": 1789351965}

{"type": "rpc_response", "id": "7f3a…", "ok": true,  "result": { }}
{"type": "rpc_response", "id": "7f3a…", "ok": false,
 "error": {"code": "path_denied", "message": "path outside allowed roots"}}

{"type": "file_chunk", "id": "7f3a…", "seq": 0, "data": "<b64>", "eof": false}
{"type": "file_chunk", "id": "7f3a…", "seq": 41, "data": "", "eof": true,
 "sha256": "…", "total_bytes": 10485760}
```

**服务端 → 连接器**

```jsonc
{"type": "registered", "node_id": "dev-a1b2c3", "heartbeat_interval_s": 20}

{"type": "rpc_request", "id": "7f3a…", "method": "fs.list",
 "params": {"path": "D:/PPT资料", "max_entries": 500}}
// method ∈ fs.list | fs.search | fs.read | fs.fetch | fs.stat

{"type": "cancel", "id": "7f3a…"}   // 终止该 id 的进行中传输，客户端立即停发
{"type": "revoked"}   // 设备被吊销，客户端应停止重连并提示用户
{"type": "error", "code": "…", "message": "…"}
```

**`fs.fetch` 响应语义**：成功时以 `file_chunk` 帧流响应（不另发 `rpc_response`），尾帧 `eof: true` 携带 sha256 与总字节数；失败（含中途出错）以 `rpc_response(ok=false)` 终止该 `id` 的流。发起方超时或 Agent 回合取消时，服务端下发 `cancel` 帧并丢弃该 `id` 的后续分块。

### 4.3 错误码

| code | 含义 | Agent 侧处理 |
|---|---|---|
| `path_denied` | 路径不在白名单 | 提示用户在连接器上授权该目录 |
| `not_found` | 文件不存在 | 换路径重试 |
| `too_large` | 超过 `maxFileBytes` | 提示用户拆分或改用摘要 |
| `node_offline` | 设备离线（服务端生成） | 提示用户启动连接器 |
| `rpc_timeout` | RPC 超时（服务端生成） | 可重试一次 |
| `protocol_unsupported` | 版本不兼容 | 提示升级连接器 |

## 5. 连接器客户端设计

### 5.1 项目结构（仓库内子项目，独立发版）

```
connector/
├── pyproject.toml               # 包名 nanobot-connector；依赖: websockets, pydantic, typer
├── README.md
├── nanobot_connector/
│   ├── __init__.py / __main__.py
│   ├── cli.py                   # typer: pair / start / allow / remove / status / service
│   ├── config.py                # ~/.nanobot-connector/config.json（pydantic, camelCase）
│   ├── client.py                # 连接循环：注册→心跳→RPC 分发；指数退避重连(1s→60s, ±抖动)
│   ├── files.py                 # 白名单校验、fs.* 处理器、分块读取
│   └── service.py               # 开机自启: Windows 服务(pywin32)/launchd plist/systemd unit
├── packaging/                   # PyInstaller spec、三平台 CI 构建脚本
└── tests/
```

### 5.2 CLI 交互

```bash
nanobot-connector pair --server wss://192.168.90.100:8765 --code AB3F7K2Q \
                       --fingerprint <证书sha256>   # 自签证书场景固定指纹
nanobot-connector allow "D:\PPT资料"        # 追加共享目录（白名单）
nanobot-connector start                      # 前台运行（守护模式由 service 子命令安装）
nanobot-connector service install            # 注册开机自启
nanobot-connector status                     # 连接状态/已共享目录/服务器地址
```

**证书信任**：默认完整 TLS 信任链校验；内网自签证书用 `--fingerprint` 固定证书指纹（配对及此后每次连接均校验）；`--insecure` 仅显式使用且每次启动输出警告，禁止作为默认行为。

### 5.3 白名单与路径安全（客户端强制，服务端不可信任前提下的最后防线）

```python
def resolve_within_roots(raw: str, roots: list[Path]) -> Path:
    p = Path(raw).resolve()          # 消解 .. 与符号链接
    for root in roots:
        if p == root or p.is_relative_to(root):
            return p
    raise PathDenied(raw)
```

- 禁止添加盘符根/文件系统根为共享目录；
- 符号链接解析后仍必须落在白名单内；
- 隐藏文件与 `roots` 外的任何路径一律 `path_denied`；
- `fs.search` 带资源上限：结果数 ≤ 50、扫描 ≤ 10s、深度 ≤ 12 层，达到任一上限返回部分结果并标记 `truncated`，避免大目录扫描阻塞心跳；
- 每次 `fs.*` 调用写本地审计日志（`~/.nanobot-connector/logs/audit.log`，滚动保留 30 天）。

### 5.4 打包分发

- PyInstaller `--onefile` 产出三平台单文件可执行程序；CI（GitHub Actions matrix: windows/macos/ubuntu）构建并附加到 Release；
- WebUI 下载页链接到 Release 资产（或由管理员镜像到内网）；
- Windows 需代码签名（避免 SmartScreen/杀软误报，证书采购列入项目风险 R1）。

## 6. WebUI 设计

新增"设备"设置页（沿用现有 React/TS 组件体系与 WS/HTTP 客户端封装）：

| 页面/组件 | 功能 |
|---|---|
| 设备列表 | 名称、平台、在线状态（绿点/灰点）、最后在线时间、共享目录摘要 |
| 添加设备向导 | ① 下载连接器 → ② 生成配对码（10 分钟倒计时）→ ③ 等待设备上线（轮询 `/api/connector/nodes`） |
| 设备详情 | 共享目录清单、吊销按钮（二次确认） |

开发期由 `webui/vite.config.ts` 现有代理配置转发 `/api` 到网关，无需新增代理规则。

## 7. 安全设计

| 威胁（STRIDE） | 对策 |
|---|---|
| 伪装（Spoofing）：伪造设备接入 | 一次性配对码（TTL 10min）+ 设备令牌哈希存储 + 握手常量时间比较 |
| 伪装（Spoofing）：暴力猜测配对码 | `/connector/pair` 来源 IP 失败 5 次锁 15 分钟 + 全局失败熔断（作废未兑换码并告警）+ 常量时间比较 |
| 伪装（Spoofing）：连接器连到假冒服务器 | 默认完整 TLS 校验；自签场景证书指纹固定（`--fingerprint`），指纹不符即断开 |
| 篡改（Tampering）：传输内容被改 | 全程 WSS（复用网关 `ssl_certfile/ssl_keyfile` 配置）；文件级 sha256 校验 |
| 篡改（Tampering）：恶意连接器路径注入落盘逃逸 | 服务端落盘 sanitize：剥离盘符/根、消解 `..`、resolve 后强制在 `<workspace>/connector/<node_id>/` 内（独立于客户端白名单的第二道防线） |
| 抵赖（Repudiation） | 服务端审计日志：`时间/会话/node_id/method/路径/字节数/结果`；客户端本地审计日志 |
| 信息泄露（Info Disclosure）：Agent 越权读文件 | 客户端白名单是唯一授权源，服务端请求一律经白名单校验；只读；单文件上限 |
| 信息泄露（Info Disclosure）：跨用户访问他人设备 | 设备记录绑定归属用户（ownerId），多用户部署按归属过滤，跨用户返回 `not_found` 不泄露存在性 |
| 拒绝服务（DoS）：恶意高频 RPC / 巨帧 / 撑爆磁盘 | 每节点 RPC 速率限制；`max_message_bytes` 沿用通道限制；传输并发上限；注册前 10s 超时踢除；落盘区 `fetchCacheMaxBytes` 配额 + LRU 清理 |
| 提权（Elevation）：借连接器执行命令 | v1 不实现任何执行类 method；`allowExec` 仅为 v2 预留且默认 false |

另：吊销即时生效（断开在线连接 + 令牌哈希标记失效）；连接器不监听任何端口（纯出站），本机攻击面最小化。

## 8. 可观测性

- **日志**：沿用 loguru 风格通道日志（`self.logger`），关键事件：注册/断开/吊销/传输开始/传输完成/校验失败。
- **指标**（暴露给现有状态接口）：在线节点数、RPC QPS 与 P95 延迟、传输成功率、字节吞吐。

## 10. 兼容性与演进

- 功能整体受 `connector.enabled` 开关控制，默认关闭 —— 对存量部署零影响；
- 协议版本协商为 v2 铺路：目录变更推送（watch）、断点续传（`fs.fetch` 带 `offset`）、受控执行（`allowExec`）、移动端；
- 连接器与服务端独立发版，注册时校验协议版本，不匹配时明确报错并提示升级路径。

## 11. 关键决策记录（ADR 摘要）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 反向连接（连接器出站） | 服务端主动连接用户电脑 | 用户电脑通常无公网/固定 IP，出站连接免开端口、免配防火墙，与 CMDB 采集器模式一致 |
| D2 | 复用网关 websockets 端口与 HTTP 分发 | 独立监听端口 | 少一个端口与证书管理成本；`process_request` 分发链已支持多路由 |
| D3 | JSON 文本帧 + base64 分块 | 二进制帧 / gRPC / 独立 HTTP 上传 | 与现有 WebUI 通道编码一致，实现与调试成本最低；256KB 分块下 base64 开销（+33%）可接受，性能瓶颈在网络而非编码 |
| D4 | 按需拉取（fetch 到工作区） | 实时同步 | 满足"做 PPT"场景即可，同步引擎复杂度与冲突处理不值得 v1 承担 |
| D5 | 客户端 Python + PyInstaller | Go/Rust 重写 | 复用团队技术栈与 nanobot 既有代码风格；体积与内存可接受（目标 ≤ 80MB） |
| D6 | v1 只读 | 读写 | 缩小安全评审面，写能力等待真实需求驱动 |
| D7 | 自签证书用指纹固定（pinning） | mTLS / 默认跳过校验 | mTLS 对个人用户部署成本过高；跳过校验不可接受；指纹固定一次配置长期有效 |
| D8 | 双向路径防线（客户端白名单 + 服务端落盘 sanitize） | 单侧校验 | 两端互不信任：白名单防越权读，落盘 sanitize 防被攻破的连接器写出落盘区 |
| D9 | 传输独立超时（transferTimeoutS）+ cancel 帧 | 复用 rpcTimeoutS | 60s 对大文件不现实；取消帧避免 Agent 回合结束后传输继续占用带宽 |
