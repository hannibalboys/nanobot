## 1. 项目背景与问题陈述

### 1.1 背景

nanobot 以服务端形态部署（如内网服务器 `192.168.90.100`），用户通过 WebUI 访问。Agent 的文件系统、Shell 等工具只能操作**服务器本地**的工作区。当用户的资料（文档、数据、素材）存放在**自己的办公电脑**上时，Agent 无法直接读取，典型场景：

> "我想让 nanobot 基于我电脑上的资料做一份 PPT，但资料没有上传到服务器。"

目前的规避手段（手动上传、挂网盘、SMB 共享）都存在明显缺陷：操作繁琐、依赖 IT 开通共享权限、无法让 Agent 主动"按需取数"。

### 1.2 业界对标

该问题在企业软件中是成熟命题，主流解法即**反向连接的轻量 Agent（采集器/连接器）模式**：

| 产品 | 组件 | 模式 |
|---|---|---|
| CMDB / Zabbix / 蓝鲸 | Agent 采集器 | 客户端主动外连服务端，注册后接受指令 |
| Microsoft 365 | OneDrive 同步客户端 | 本地守护进程 + 云端配对 |
| Teleport / 向日葵 / ToDesk | 节点 Agent | 出站长连接穿透 NAT，服务端反向调度 |
| VS Code Remote Tunnels | tunnel 守护进程 | 设备码配对 + 出站隧道 |
| Anthropic/OpenAI 生态 | 本地 MCP Server | 本地进程暴露受控能力给远端模型 |

**结论**：本项目采用同样的"下载安装轻量连接器 → 设备配对 → 出站长连接 → 服务端按需调用"模式，命名为 **nanobot Connector**。

### 1.3 项目目标（SMART）

| # | 目标 | 度量标准 | 期限 |
|---|---|---|---|
| G1 | 交付 Windows/macOS/Linux 三平台连接器安装包 | WebUI 可下载，安装成功率 ≥ 99% | GA |
| G2 | Agent 可检索/读取/拉取已授权的本地文件 | "本地资料做 PPT" 端到端场景通过 | GA |
| G3 | 安全达标 | 通过安全评审：目录白名单、只读默认、令牌可吊销、全程 TLS、审计日志 | 安全评审门禁 |
| G4 | 稳定性达标 | 断线自动重连 ≤ 30s；连接器常驻内存 ≤ 80MB；7×24 稳定运行 | 灰度结束 |
| G5 | 可运维 | 设备管理页（在线状态/吊销/日志）、监控指标、升级通道 | GA |

### 1.4 不做什么（Out of Scope, v1）

- ❌ 本地文件的**双向实时同步**（非网盘产品）
- ❌ 默认开启本地 Shell 执行（作为高危能力仅保留配置开关，默认关闭，v2 再评估）
- ❌ 移动端（iOS/Android）连接器
- ❌ P2P 直连/中继网络（v1 全部流量经 nanobot 网关中转）
- ❌ 服务端对本地文件的写入/删除（v1 只读）

### S3 开发迭代（W4–W7，3 个 Sprint）

**Sprint 1（W4–W5 上）— 通道打通**

- 服务端：`/connector/ws` 网关端点、设备注册/心跳、ConnectorHub 节点管理、设备令牌签发与存储
- 客户端：连接器骨架（CLI + 守护进程）、配对流程、断线重连
- 前端：设备管理页（列表/在线状态/生成配对码）
- **Sprint 验收**：连接器在 Windows 上完成配对并保持在线，服务端可见节点心跳

**Sprint 2（W5 下–W6）— 文件能力**

- 服务端：`connector_list_nodes` / `connector_list_files` / `connector_search_files` / `connector_read_file` / `connector_fetch_file` 五个 Agent 工具；文件分块传输与落盘
- 客户端：目录白名单引擎、文件枚举/搜索/分块上传、大小与类型限制
- 前端：设备详情页（授权目录展示、吊销按钮）
- **Sprint 验收**：在 WebUI 对话中让 Agent 列出并拉取本机白名单目录下的文件

**Sprint 3（W7）— 端到端与打磨**

- 端到端场景：本地资料 → Agent 拉取 → 生成 PPT 交付
- 三平台打包（PyInstaller）、安装脚本、开机自启（Windows 服务 / launchd / systemd）
- 审计日志、限流、指标埋点
- **Sprint 验收**：三平台安装包冒烟通过；PPT 场景演示通过

**门禁 G-S3**：功能演示通过；单测覆盖率 ≥ 80%（新增代码）；`ruff check` 零告警。

### S4 系统测试与安全评审（W8–W9）

| 测试项 | 内容 | 通过标准 |
|---|---|---|
| 功能测试 | 全用例回归 | P0/P1 缺陷清零 |
| 兼容性 | Win10/11、macOS 13+、Ubuntu 20.04+ | 全平台通过 |
| 可靠性 | 断网/杀进程/服务端重启/弱网 | 重连 ≤ 30s，无数据损坏 |
| 性能 | 100 节点并发心跳；500MB 文件传输 | 网关 CPU < 30%；传输可续传 |
| 安全渗透 | 双向路径逃逸（客户端白名单 + 服务端落盘）、配对码暴力猜测、令牌重放、越权访问他人节点、假冒服务器/中间人 | 无高危漏洞 |
| 升级/回滚 | 连接器旧版本兼容、协议版本协商 | 协商降级正常 |

**门禁 G-S4**：QA 测试报告 + 安全渗透报告双签通过。

### S5 灰度发布（W10–W11 上）

- 内部试点 5–10 名用户，覆盖三平台
- 每周收集 NPS 与缺陷，48h 内修复 P0/P1
- 监控看板观察：节点在线率、RPC 成功率、传输失败率

**退出标准**：连续 5 个工作日无 P0/P1；节点在线率 ≥ 99%；试点用户满意度 ≥ 4/5。

### S6 GA 与移交（W11 下–W12）

- 正式发布：版本打 tag、WebUI 下载入口全量开放
- 文档交付：用户手册、FAQ、运维手册（部署/监控/告警/升级）
- OpenSpec 归档：`openspec archive add-nanobot-connector`
- 项目复盘会与经验沉淀

## 9. 验收标准（GA Definition of Done)

1. 用户在 WebUI 下载连接器 → 安装 → 输入配对码 → 设备上线，全流程 ≤ 5 分钟
2. 用户在对话中说"用我电脑 D:\资料 里的素材做一份 PPT"，Agent 能列出文件、拉取所需文档、产出 PPT 并通过 WebUI 交付
3. 管理员可在 WebUI 查看/吊销任意设备；吊销后连接器 10s 内断开且无法重连
4. 三平台安装包 + 用户手册 + 运维手册齐套
5. 安全渗透报告无高危项；审计日志覆盖全部文件访问
6. `openspec archive add-nanobot-connector` 完成，规格归档到 `openspec/specs/`
