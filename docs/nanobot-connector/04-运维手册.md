# nanobot Connector 运维手册

> 原理概述见 [00-连接器说明](./00-连接器说明.md)。

## 启用与关闭

`~/.nanobot/config.json`：

```json
{
  "connector": {
    "enabled": true,
    "path": "/connector/ws",
    "pairingCodeTtlS": 600,
    "rpcTimeoutS": 60,
    "transferTimeoutS": 600,
    "maxFileBytes": 209715200,
    "fetchCacheMaxBytes": 2147483648
  }
}
```

- **启用**：`enabled: true` 后重启 `nanobot gateway`
- **紧急关闭**：`enabled: false` 并重启；`/connector/ws` 与 `/api/connector/*` 返回 404，在线连接断开

## 受控执行（allowExec，v2）

受控本地工具执行**独立于文件能力**，由单独开关控制，默认关闭：

```json
{
  "connector": {
    "enabled": true,
    "allowExec": false,
    "maxConcurrentExecs": 2,
    "execTimeoutS": 300,
    "maxExecOutputBytes": 1048576,
    "approvalTtlS": 120,
    "execRatePerMinute": 30
  }
}
```

- `allowExec` 为 false 时：`connector_list_tools`/`connector_call_tool` 工具不注册，`tools.*` 路由与执行管理路由（`/api/connector/tools|grants|grant|revoke-grant|requests|deny-request|approvals|approve|exec-metrics|exec-audit`）全部 404。文件能力不受影响。
- `maxConcurrentExecs`：每设备并发执行上限；`execTimeoutS`：单次执行墙钟超时（超时终止进程树）；`maxExecOutputBytes`：单次输出累计上限（超限截断）；`approvalTtlS`：审批等待超时，**到期默认拒绝**；`execRatePerMinute`：每操作者/每设备执行速率上限（命中返回 `exec_limit`）。
- **紧急收束执行**：仅关 `allowExec`（保留文件能力）并重启，或整体 `enabled: false`。

### 本地 MCP 代理（allowMcpProxy，v2.5）

在 `allowExec` 之上再开 `allowMcpProxy`（默认关），连接器可把设备本机运行的 MCP server 桥接为服务端原生工具：

```json
{ "connector": { "enabled": true, "allowExec": true, "allowMcpProxy": true } }
```

- 三重开关：`enabled` + `allowExec` + `allowMcpProxy` 全开，`connector_list_mcp_tools`/`connector_call_mcp_tool` 才注册，`/api/connector/mcp-tools` 才可用；任一关闭即 404。
- 连接器作为 MCP 客户端连本机 server（stdio 子进程由其 spawn/kill；http 型由用户自运行），服务端**不直连**用户电脑。设备下线自动注销其桥接工具。
- 桥接工具沿用 v2 授权/审批/审计/限流/指标；授权键为 `mcp:<server>:<tool>`，与本地工具键不冲突。server 凭据只存本机（`mcp.json` 的 `secrets` 引用 + `tool secret set`），不经协议。
- 治理提示：一个 MCP server 可能带来一整套高权限工具，建议对高危 server 设 `approval=local` 或 `webui`，并用 `enabledTools` 收窄。
- 单个服务可通过其本机 `mcp.json` 的 `enabled: false` 停止桥接但保留定义；连接器 GUI 的 MCP 服务列表提供右键详情、测试、启动、停止和实时连接状态，适合排障与日常运维。

### 受控桌面控制（allowDesktopControl，v3）

**最高风险能力**，与 `allowExec` 独立，默认关闭：

```json
{
  "connector": {
    "enabled": true,
    "allowDesktopControl": true,
    "desktopMaxFps": 2,
    "desktopMaxDimension": 1280,
    "desktopSessionMaxS": 900,
    "desktopIdleTimeoutS": 120,
    "desktopRecordingRetentionDays": 7
  }
}
```

- 三方门禁：网关 `allowDesktopControl` + 设备本机 `desktopEnabled` + 可用的交互式桌面环境，缺一不可。Windows 10/11 没有单独的“屏幕录制/辅助功能”授权页；连接器须在当前已登录用户会话中运行。macOS 仍需授予屏幕录制和辅助功能权限。
- 结构上强制人在环：**无 `auto`**——每次会话由设备本机同意放行（守护进程经 arm 时间窗 `nanobot-connector arm desktop --for 30m` 预授权，未 arm 即 fail-closed 拒绝，到期自动失效）；敏感动作（支付/确认/删除/授权/密码输入）经 WebUI 二次确认（`approvalTtlS` 到期默认拒绝）。
- 限时：`desktopSessionMaxS` 最长时长 + `desktopIdleTimeoutS` 空闲超时，到点自动结束并释放；断连即结束。
- 隐私：屏幕帧**默认不落盘**；仅显式录制才写 `<workspace>/connector/desktop-recordings/<session>/`，按 `desktopRecordingRetentionDays` 到期自动清理（`cleanup_recordings`），可手动删除。逐动作审计写 `<workspace>/connector/desktop-audit.log`（动作/参数摘要/是否敏感/是否确认/截图引用/结果）。
- 跨人：操作者非设备主人时需 per-device 授权键 `desktop:control`；且仍需设备本机在场同意。
- 管理路由：`/api/connector/desktop-sessions`（活跃会话）、`/api/connector/desktop-takeover`（接管/终止），仅 `allowDesktopControl` 开启且按归属过滤。
- **紧急收束**：关 `allowDesktopControl` 并重启（会话不可开启，文件/执行能力不受影响）。

### 授权治理

- **操作者 ≠ 设备主人** 时为跨人使用，须设备主人显式授予（per-device / per-tool，可限时）。未授权跨人调用统一返回等同 `not_found`，不泄露工具存在性。
- 授权数据持久化于 `<workspace>/connector/grants.json`（授予 + 待处理访问请求）。
- 设备主人主权：工具定义/凭据只存设备本机，服务端无法远程新增工具、提权或绕过 `local` 审批；收回授权即时生效。
- WebUI（**Settings → Devices → 管理**）提供：本地工具查看、授权授予/收回、待处理请求接受/拒绝、活跃使用者、设备别名、审计历史。

### 执行监控指标

`GET /api/connector/exec-metrics`（需 WebUI 鉴权）返回：执行次数、失败率、审批拒绝数、限流命中数、时长 p50/p95、按设备计数。建议监控：

- 审批拒绝率 / 限流命中突增（可能被滥用或配置过紧）
- 失败率、p95 时长异常
- 单设备执行次数异常放大

## 网络与 TLS

- 连接器仅**出站**连接网关，用户电脑无需开端口
- 需放行客户端到网关的 WSS（或 WS）端口
- 生产环境建议使用有效 TLS 证书；内网自签时指导用户使用 `pair --fingerprint`

## 数据与存储

| 路径 | 内容 |
|---|---|
| `<workspace>/connector/devices.json` | 设备令牌哈希、归属、吊销状态、设备别名 |
| `<workspace>/connector/grants.json` | 跨人授权与待处理访问请求（v2） |
| `<workspace>/connector/<node_id>/` | Agent 拉取的文件缓存（LRU，默认上限 2GB） |
| `<workspace>/connector/audit.log` | 服务端文件访问审计 |
| `<workspace>/connector/exec-audit.log` | 服务端执行审计（工具/操作者/审批方式/退出码/耗时，参数脱敏）|
| `<workspace>/connector/desktop-audit.log` | 桌面控制逐动作审计（动作/是否敏感/是否确认/截图引用/结果）|
| `<workspace>/connector/desktop-recordings/<session>/` | 仅显式录制时的屏幕帧（按保留期到期清理）|

## 监控建议

- 在线节点数、RPC 失败率、传输失败率
- 配对失败突增（可能暴力猜码，检查 429 与熔断日志）
- 落盘区磁盘占用接近 `fetchCacheMaxBytes`

## 故障 Runbook

### 设备显示离线

1. 用户本机 `nanobot-connector status`
2. 检查网关进程与 `/connector/ws` 可达性
3. 检查设备是否被吊销（`devices.json` 中 `revoked: true`）

### 配对码无效

- 配对码 TTL 默认 10 分钟、一次性
- 同一 IP 连续失败 5 次锁定 15 分钟
- 全局熔断会作废所有未兑换配对码（查网关日志 `circuit breaker`）

### 传输失败 / too_large

- 单文件超过 `maxFileBytes`（默认 200MB）
- 落盘区满触发 LRU 或单文件超配额
- 调大 `transferTimeoutS` 应对慢网络

### 执行相关（allowExec 开启时）

- **工具不存在（tool_not_found）**：未登记，或跨人调用未获授权（有意与 not_found 同码）
- **未获批准（approval_denied/超时）**：`webui` 无人放行到 `approvalTtlS`，或 `local` 被设备主人拒绝
- **限流（exec_limit）**：超 `execRatePerMinute` 或 `maxConcurrentExecs`；确认非滥用后可上调
- **执行超时/取消**：超 `execTimeoutS` 或被取消，连接器终止进程树；查 `exec-audit.log`
- **设备不支持执行（exec_unsupported）**：v1 连接器无 `exec` 能力，提示用户升级

### 安全事件

- **可疑路径访问**：查 `audit.log` 与客户端本地审计
- **可疑执行**：查 `exec-audit.log`（含操作者/工具/审批方式/结果）与 `exec-metrics`
- **令牌泄露**：WebUI 吊销设备，用户重新配对
- **越权/滥用他人设备**：设备主人在"活跃使用者"一键收回授权；必要时关 `allowExec`
- **假冒服务器**：用户应使用证书指纹固定，禁止默认 `--insecure`

## 升级

- 网关与连接器**独立发版**，协议版本在 `register` 帧协商
- 升级顺序建议：先升级网关，再推送连接器安装包
- 回滚：关闭 `connector.enabled` 或回退网关版本；连接器旧版应能收到 `protocol_unsupported` 提示
