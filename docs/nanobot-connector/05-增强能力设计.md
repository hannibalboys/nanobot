# nanobot Connector 增强能力设计（受控执行 / 本地 MCP 代理 / 桌面控制）

> **文档编号**: NBC-TD-002
> **版本**: v1.0
> **状态**: 现行
> **配套文档**: [00-连接器说明](./00-连接器说明.md)、[02-技术设计](./02-技术设计.md)（v1 只读基线）、[03-用户手册](./03-用户手册.md)、[04-运维手册](./04-运维手册.md)

## 1. 概述与能力分层

v1 让 Agent **只读**用户本机白名单目录。本文描述在 v1 反向连接 / 配对 / 令牌 / 归属地基之上的三档能力增强——把"只能看"升级为"受控地动手"，并支持**一个服务器大脑外连多台（他人的）电脑**的多用户场景。

| 档位 | 能力 | 开关 | Agent 工具 |
|---|---|---|---|
| v1 | 只读文件（列/搜/读/取） | `enabled` | `connector_list_nodes` / `_list_files` / `_search_files` / `_read_file` / `_fetch_file` |
| v2 | 受控执行本地登记的工具 | `enabled`+`allowExec` | `connector_list_tools` / `connector_call_tool` |
| v2.5 | 桥接本机 MCP server | `enabled`+`allowExec`+`allowMcpProxy` | `connector_list_mcp_tools` / `connector_call_mcp_tool` |
| v3 | 受控桌面控制（截屏+键鼠） | `enabled`+`allowDesktopControl` | `connector_desktop_session` / `_act` / `_end` |

所有增强开关**默认关闭**，对存量部署与 v1 用户零影响。

**核心安全立场**：服务端不可信、命令不由服务端构造、设备主人对本机能力有最终主权。三档共用同一套授权/审批/审计地基（v2 建立，v2.5/v3 复用）。

## 2. 协议演进（v1 → v2）

协议帧仍是单条 WSS 上的 JSON，`type` 判别、`extra="allow"` 向前兼容。`PROTOCOL_VERSION` 由 1 升到 2，注册时协商。

### 2.1 能力协商

`register` 帧的 `node.capabilities` 声明本连接器支持的能力集：

- `fs`（v1 基线，默认）、`exec`（v2）、`mcp`（v2.5）、`desktop`（v3）。
- v1 连接器不带 `capabilities` → 默认 `["fs"]`，连 v2 服务端时自动降级为只读。
- 服务端按能力交集路由：对不声明 `exec` 的节点调用执行工具 → 返回 `exec_unsupported`。

### 2.2 方法集

| 方法组 | 方法 | 能力 |
|---|---|---|
| `FS_METHODS` | `fs.list` / `fs.search` / `fs.read` / `fs.stat` / `fs.fetch` | `fs` |
| `EXEC_METHODS` | `tools.list` / `tools.call` / `tools.cancel` | `exec` |
| `MCP_METHODS` | `mcp.list` / `mcp.call` | `mcp` |
| `DESKTOP_METHODS` | `desktop.session.start` / `.end` / `desktop.capture` / `desktop.input` | `desktop` |

### 2.3 新增帧

- `exec_output`（stdout/stderr 增量流，`stream`+`seq`）、`exec_result`（exitCode/durationMs/timedOut/truncated/cancelled）。
- MCP / 桌面调用为普通 `rpc_request`/`rpc_response`（桌面 capture 返回内联图像 base64）。

### 2.4 稳定错误码

三层（协议/网关/工具）共享同一套码，工具层据此映射为面向 LLM 的可操作文案：

- 执行：`exec_unsupported` / `tool_not_found` / `invalid_args` / `missing_credential` / `exec_denied` / `approval_denied` / `approval_timeout` / `exec_limit` / `exec_timeout` / `exec_cancelled`
- MCP：`mcp_unsupported` / `mcp_unavailable`
- 桌面：`desktop_unsupported` / `session_inactive` / `session_ended` / `out_of_bounds` / `no_permission` / `sensitive_unconfirmed`

## 3. 安全模型总览（贯穿三档）

### 3.1 操作者 vs 设备主人

- **操作者（operator）**：与 nanobot server 对话、发起调用的会话用户。
- **设备主人（owner）**：连接器所在电脑的所有者（`Device.owner_id`）。
- 二者相同 = 自用；不同 = **跨人使用**（本项目核心多用户场景）。

### 3.2 授权（静态）

`nanobot/connector/authz.py` 的 `AuthorizationStore`（持久化 `grants.json`）：

- 自用（operator == owner）默认放行。
- 跨人须设备主人经**访问请求→接受**或主动授予；授权 per-device / per-tool、可限时（TTL）。
- 授权键：执行工具用工具名；MCP 用 `mcp:<server>:<tool>`；桌面用 `desktop:control`。三者隔离、不冲突。
- 未授权跨人调用统一返回等同 `not_found`，**不泄露工具/能力存在性**。
- 设备主人随时收回，即时生效；活跃使用者视图可见"谁在用、用了哪些"。

### 3.3 审批（动态，每次调用）

`ExecutionCoordinator` + `ApprovalBroker`（`nanobot/connector/exec.py`）：

| 策略 | 行为 |
|---|---|
| `auto` | 授权内直接执行（建议仅自用低危工具）|
| `webui` | 服务端弹审批卡片，WebUI 放行后才执行；`approvalTtlS` 到期**默认拒绝** |
| `local` | 连接器本机确认（fail-closed：无同意即拒绝）|

桌面控制**不提供 `auto`**：开启会话必须设备本机在场同意；敏感动作走 `webui` 二次确认。

**本机同意（arm 时间窗）**：无人值守守护进程无法弹交互式确认，故 `local` 与桌面的"本机同意"由设备主人经 CLI 预授权一个限时窗口实现（`nanobot_connector/arm.py` 的 `ArmStore`，持久化 `arm.json`、mode 0600）：

- `nanobot-connector arm <exec|mcp|desktop> --for 30m` / `disarm [category|all]` / `arm status`。
- 守护进程的同意钩子（`build_daemon_client`）在每次判定时**重读 arm.json**，故 arm/disarm 即时生效、到期自动失效，无需重启。
- 未 arm → fail-closed 拒绝。桌面会话即使 arm 也仍受会话限时/空闲/接管约束。

### 3.4 凭据只存本机

工具/ MCP server 的 token/密钥只存设备本机（`secrets.json`，0600），执行时注入子进程环境。协议帧、服务端状态、审计**只出现引用名与脱敏摘要**，绝无明文。

### 3.5 资源上限与限流

- 执行：并发 `maxConcurrentExecs`、单次 `execTimeoutS`、输出 `maxExecOutputBytes`（截断）、per-operator/per-device `execRatePerMinute`。
- 桌面：帧率/分辨率上限（服务端下发、客户端 clamp）、会话最长时长、空闲超时。

### 3.6 审计（强制、不可关闭）

- 文件访问：`connector/audit.log`。
- 执行：`connector/exec-audit.log`（操作者/工具/审批方式/退出码/耗时，参数脱敏）。
- 桌面：`connector/desktop-audit.log`（逐动作、是否敏感/确认、截图引用；键入 `text` 仅记长度）。

## 4. v2 受控执行（connector-local-tools）

### 4.1 声明式工具注册表（客户端）

设备主人在本机 `~/.nanobot-connector/tools.json` 登记工具（`tool add/list/remove`）：`name` / `exec` / 参数模板 / `workdir` / `timeout` / `approval` / 凭据引用。

- 参数模板类型：`string`（`pattern`）、`int`（`min`/`max`）、`enum`（`choices`）、`path`（`allowedDir` 强制目录内）。
- 渲染为 `argv` 数组，**`shell=False` 执行**——shell 元字符只是普通字符串，杜绝注入。
- 服务端**不能**远程新增/改写工具或凭据。

### 4.2 执行器（客户端 `runner.py`）

`shell=False` 子进程、增量回传 stdout/stderr、进程树终止（Windows 进程组 + POSIX `setsid`/`killpg`）、超时与输出上限截断、凭据注入。

### 4.3 服务端

- `ConnectorHub.list_tools/call_tool`：复用 request-id + 队列转发 `exec_output`、`exec_result` 终止、断连清理、`cancel` 终止执行。
- `ExecutionCoordinator`：限流 → 授权 → 审批 → 执行 → 指标 + 审计。
- 取消传播：Agent 回合取消时向设备下发 `cancel`，避免孤儿进程。

## 5. v2.5 本地 MCP 代理（connector-mcp-proxy）

### 5.1 思路

设备主人在本机 `mcp.json` 登记正在运行的 MCP server（`mcp add/list/remove`，沿用 stdio/sse/streamableHttp）；连接器作为 **MCP 客户端**连它们，把工具清单与调用经连接器通道转发。服务端不直连用户电脑。

> 设计取舍：采用"连接器做 MCP client + 服务端结构化转发 + 发现-调用工具"，而非"透明 JSON-RPC 隧道复用 mcp.py transport"。前者把 MCP 往返留在本机（低延迟）、天然适配设备动态上下线、避免灌爆 provider 词表，并与其余 `connector_*` 工具风格一致。

### 5.2 要点

- 每 server 的 SDK 上下文由单一 asyncio 任务持有（AnyIO 取消域要求）；健康监控 + 自动重连。
- 桥接工具经协调器统一走 v2 授权（键 `mcp:<server>:<tool>`）/ 审批 / 审计 / 限流 / 指标。
- server 凭据只存本机、注入子进程，不经协议。
- 设备下线其桥接工具即不可见（`mcp_status`/调用返回不可用）。

## 6. v3 受控桌面控制（connector-desktop-control）

最高风险能力，独立开关 `allowDesktopControl`，与 `allowExec` 无关。

### 6.1 会话生命周期（`DesktopSessionManager`）

- 开启：跨人需 `desktop:control` 授权；**必经设备本机在场同意**（客户端 `on_local_authorize`，fail-closed）；返回首屏截图。
- 驱动：`connector_desktop_act` 注入一个动作并返回下一屏——computer-use 闭环由 **Agent 自身多模态循环**驱动（截图作为工具结果回模型）。
- 结束：`connector_desktop_end` / 接管 / 超时 / 空闲 / 断连——**任一情况都向设备下发 `session.end`，捕获与注入立即停止**。

### 6.2 人在环 + 敏感确认

- 无 `auto`；设备主人可随时接管/终止（`/api/connector/desktop-takeover`）。
- 敏感动作（支付/确认/删除/授权语义控件、密码类输入）经 `webui` 二次确认，未确认不注入。

### 6.3 隐私

- 屏幕帧**默认仅内存流转、不落盘**；仅 `record=True` 才写 `desktop-recordings/<session>/`。
- 录制按 `desktopRecordingRetentionDays` 到期自动清理，可手动删除（防路径穿越、删除记审计）。
- 捕获期间设备本机显示醒目指示；逐动作审计支持回放（`/api/connector/desktop-audit`）。

### 6.4 边界校验

动作类型白名单（`DESKTOP_ACTIONS`）+ 坐标屏内校验（客户端，依据最近一帧尺寸）；服务端下发帧率/分辨率上限，客户端取 `min(本机, 服务端)`。

## 7. 配置参考（`ConnectorConfig` 新增字段）

| 字段（camelCase） | 默认 | 说明 |
|---|---|---|
| `allowExec` | false | 启用受控执行（v2）|
| `maxConcurrentExecs` | 2 | 每设备并发执行上限 |
| `execTimeoutS` | 300 | 单次执行超时 |
| `maxExecOutputBytes` | 1048576 | 单次输出累计上限（截断）|
| `approvalTtlS` | 120 | 审批等待超时（到期默认拒绝）|
| `execRatePerMinute` | 30 | per-operator/per-device 执行速率 |
| `allowMcpProxy` | false | 启用本地 MCP 代理（v2.5，需 allowExec）|
| `allowDesktopControl` | false | 启用桌面控制（v3）|
| `desktopMaxFps` | 2 | 捕获帧率上限 |
| `desktopMaxDimension` | 1280 | 捕获长边像素上限 |
| `desktopSessionMaxS` | 900 | 会话最长时长 |
| `desktopIdleTimeoutS` | 120 | 空闲自动结束 |
| `desktopRecordingRetentionDays` | 7 | 录制保留期 |

客户端（`~/.nanobot-connector/config.json`）另有：`desktopEnabled`、`desktopMaxFps`、`desktopMaxDimension`、`execTimeoutS`、`maxExecOutputBytes`。

## 8. Agent 工具参考

| 工具 | 开关 | 作用 |
|---|---|---|
| `connector_list_tools(node_id)` | allowExec | 列设备已登记工具 |
| `connector_call_tool(node_id, tool, args)` | allowExec | 调用已登记工具 |
| `connector_list_mcp_tools(node_id)` | allowMcpProxy | 列桥接的 MCP 工具 |
| `connector_call_mcp_tool(node_id, server, tool, args)` | allowMcpProxy | 调用桥接 MCP 工具 |
| `connector_desktop_session(node_id, goal)` | allowDesktopControl | 开会话，返回首屏 |
| `connector_desktop_act(session_id, action)` | allowDesktopControl | 注入动作，返回下一屏 |
| `connector_desktop_end(session_id)` | allowDesktopControl | 结束会话 |

`node_id` 必填，多设备不隐式任选；`connector_list_nodes` 返回设备别名辅助定向。

## 11. 开关矩阵与回滚

- 逐级开启：`enabled` →（+`allowExec`）→（+`allowMcpProxy`）；`allowDesktopControl` 独立。
- 紧急收束：关某一开关并重启，对应工具不注册、路由 404、能力立即消失；下层能力不受影响。
- 灰度：先用低危工具（"打开记事本"/只读诊断脚本）跑通 list→授权→审批→执行→取消→审计全链路。

## 12. 设计取舍与后续增量

- **发现-调用 vs 原生注册（MCP）**：见 §5.1。
- **Agent 驱动 vs 服务端 LLM 循环（桌面）**：见 §6.1，复用 Agent 多模态能力，避免重复集成。
- **后续增量**：WebUI 执行实时输出流、桌面实时画面流式预览（需 WS 多路复用）；MCP resources/prompts 代理；桌面协作模式（人机交替控制）。
- **GA 门禁**：三档均需专项安全评审 / 渗透测试（v3 另需隐私影响评估）通过后方可 `openspec archive`。
